# 5分钟实时K线与信号存储

数据库默认位置：

`%LOCALAPPDATA%\TVFloat\market.db`

悬浮行情会读取其中尚未确认的 A/B 级信号：做多为绿色闪烁，做空为红色闪烁。
点击对应标的后，程序会确认并停止该标的的提醒，同时优先切换到 TradingView
Desktop 顶部已经打开的同名图表标签；找不到标签时才使用 TradingView 链接兜底。

测试或多实例环境可通过 `TVFLOAT_SIGNAL_DB` 环境变量临时指定另一份数据库。

初始化：

```powershell
python .\realtime_signals\kline_store.py init
```

本程序只负责可靠地增量保存K线、市场状态和信号。实时任务通过
TradingView MCP读取与图表一致的数据，然后调用本程序写入SQLite。

## 数据约定

- 数据库时间统一为Unix UTC秒。
- 品种固定为：
  - `BYBIT:BTCUSDT.P`
  - `OANDA:XAGUSD`
  - `OANDA:XAUUSD`
  - `ICMARKETS:US500`
- 周期固定为 `5`。
- 只对已经收盘的K线产生正式信号。
- `(vendor, symbol, timeframe, open_time)` 是唯一键，重复写入不会制造重复K线。
- 相同时间、方向和类型的信号也会自动去重。
- 新信号保持未确认状态；悬浮窗点击对应标的后写入确认时间并停止闪烁。

## 实时任务判断原则

1. 先确定外层市场阶段，再判断内层结构。
2. 交易类型限定为：
   - 震荡内部：边缘反向
   - 震荡突破：位移突破
   - 宽通道边缘：反向波段
   - 宽通道突破：更大级别反转
   - 宽通道顺势：在有利边缘跟随主方向
   - 窄通道：等待回踩顺势参与
3. 相邻K线的相近影线只能算一次测试。
4. 宽通道顺势信号自动降一级。
5. 震荡中部不发正式信号。
6. 下跌/上涨高潮的第一次反转只观察；需要失败延续、收回或二次反转确认。
7. 每次判断只能使用信号K收盘时已经存在的数据。

## 紧凑上下文

`snapshot` 命令会返回：

- 最近窗口的高低点；
- EMA20和EMA50；
- 已确认摆动高低点；
- 上一次市场状态；
- 最近若干根压缩K线。

这样每5分钟无需把全部历史K线再次交给分析模型。

## 唯一生产候选层

定时采集只调用 `candidate_filter_production.py`。四个正式品种每一根已
收盘5分钟K线都会进入原文档规则复核。候选层不会直接产生正式信号。

`candidate_filter.py` 与 `candidate_filter_v2.py` 中的旧函数只保留给历史
离线回放；直接运行这两个旧文件也会强制转交唯一生产实现。生产不得使用
其中的ATR、百分比、K线位置、评分或冷却硬门槛。

生产候选只负责把已收盘K线及当时可见的OHLC、人工区间与既有信号上下文
送交AI。AI只能使用交接目录中的Louie原文与用户明确纠正规则，不满足原文
时必须否决；本地程序不得补充任何数值硬门槛。

候选发送记录保存在 `%LOCALAPPDATA%\TVFloat\candidate_memory.json`，仅用于
防止同一根已收盘K线重复提交，不得作为信号冷却或筛选条件。

## 五分钟时限与复核执行

采集任务完成每根收盘K线入队后会立即启动复核，不再等待单独的“延迟两分钟”
任务。多个候选并行交给模型，模型只输出严格的结构化判断；数据库写入、
旧警报清理、TradingView 标注和新警报创建由本地执行器完成。

- 每轮硬截止时间为下一根5分钟K线开始前15秒。
- 定时任务在整5分钟边界启动后先等待到收盘后第6秒，再计算已收盘
  数据截止点，避免刚收盘K线被错误推迟到下一轮。
- AI决策阶段至少为本地执行预留60秒。
- 超过决策截止时间的候选会被终止并记录为 `deadline_timeout`，不会在后续
  K线期间补发过时信号。
- 只有没有新收盘K线时才无候选；所有新收盘K线均进入完整原文规则复核。
- 每个候选都会从本地数据库生成一张严格截止到候选K线的复合图：上半部
  为36小时外层视图，下半部为9小时内层视图。AI依据原文规则和图像市场
  状态复核，不存在本地数值硬门槛。
- 在没有候选的空闲轮次，最多每小时生成一次四品种视觉状态基线；基线
  使用一张四宫格图并缓存到
  `%LOCALAPPDATA%\TVFloat\visual_baseline.json`，不会挤占候选复核时限。
- 模型调用的token数写入复核日志和`job_runs.detail_json`，小时基线token
  写入`%LOCALAPPDATA%\TVFloat\visual_baseline.log`。
- Windows任务只需启用 `TVFloat-LowToken-Collector`；
  `TVFloat-LowToken-Review` 是旧链路，应保持禁用。

冻结区间回放工具：

```powershell
python .\realtime_signals\candidate_replay_compare.py
```

回放报告默认写入：

`%LOCALAPPDATA%\TVFloat\candidate_replay_comparison.json`

## Excel 信号归档

全部正式信号会同步到：

`outputs\tvfloat_signal_excel\TVFloat_信号记录.xlsx`

工作簿包含概览、信号明细和字段说明。明细按信号成立时间倒序排列，
记录信号价、确认价、失效价、市场状态、完整理由、警报与AI复核结果。
“事后结果、实际结果说明、复盘备注”三列允许人工填写；自动刷新会按
信号ID保留这些内容。

新信号完成数据库、图表标注和警报处理后，本地执行器会通过隐藏进程
触发 `export_signals_excel.ps1`。多个相近信号由互斥锁合并处理；没有
新信号时不会重建工作簿，也不会调用模型或消耗额外模型 token。

## 人工震荡区间层

- TradingView 图上的橙色矩形统一解释为震荡区间。数据采集时会同步其
  5分钟起止时间和上下边界到 `chart_ranges`，不需要模型参与。
- 系统自动识别的新区间也使用橙色矩形，并在数据库中标记为 `auto`。
  用户移动或缩放该矩形后，它会提升为锁定的 `manual` 区间；以后分析
  必须采用用户修改后的精确边界。
- 用户自行添加的橙色矩形立即成为锁定的 `manual` 区间。删除矩形会
  形成删除记录，自动流程不会在相同位置反复重建它。
- 每次候选复核图都会先绘制当时有效的区间层。人工区间优先于由 OHLC
  推断的临时区间，程序不得自行拆分、缩小或替换人工区间。
- 视觉区间地图常规最多每小时更新一次；出现靠近边缘、突破、回踩或
  状态转换候选时可提前更新。普通5分钟收盘不重复调用视觉模型。
